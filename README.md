# Address Book API

A minimal, production-minded REST API for managing an address book, built with **FastAPI**, **SQLAlchemy 2.0** and **SQLite**. Clients can create, update and delete addresses (each with geographic coordinates) and search for addresses within a given distance of a location.

## Features

- Full CRUD for addresses, including partial updates (`PATCH`).
- Strict input validation with Pydantic (coordinate ranges, non-blank text, length limits).
- Persistence in SQLite; the database and tables are created automatically on first start.
- Proximity search: find addresses within *N* kilometres of a latitude/longitude, sorted nearest first, with the distance included in each result.
- Interactive API documentation (Swagger UI) generated by FastAPI; no GUI needed.
- Structured logging of create, update, delete and search operations.
- Automated test suite (pytest).

## Tech stack

| Concern | Choice | Why |
|---|---|---|
| Web framework | FastAPI | Typed, async-ready, automatic OpenAPI docs |
| Validation | Pydantic v2 | Declarative validation and serialisation |
| ORM / DB | SQLAlchemy 2.0 + SQLite | Zero-setup storage with a clean path to another database |
| Server | Uvicorn | Standard ASGI server for FastAPI |
| Tests | pytest + httpx | FastAPI's `TestClient` with an isolated in-memory DB |

## Project structure

```
address_book/
├── app/
│   ├── main.py            # App factory, logging setup, startup (creates tables)
│   ├── config.py          # Settings read from environment variables
│   ├── database.py        # Engine, session factory, get_db dependency
│   ├── models.py          # SQLAlchemy ORM model
│   ├── schemas.py         # Pydantic request/response models and validation
│   ├── crud.py            # Database operations (no HTTP concerns)
│   ├── geo.py             # Haversine distance and bounding-box helpers
│   └── routers/
│       └── addresses.py   # HTTP endpoints
├── tests/
│   └── test_api.py
├── requirements.txt
└── README.md
```

The code is layered so each piece has one job: **routers** handle HTTP, **crud** handles persistence, **schemas** handle validation, and **geo** holds pure distance maths that is easy to test.

## Getting started

Requires **Python 3.10+**.

### Windows (PowerShell)

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
uvicorn app.main:app --reload
```

### macOS / Linux

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload
```

The API is then available at <http://127.0.0.1:8000>. Open **<http://127.0.0.1:8000/docs>** for the interactive Swagger UI, where every endpoint can be tried directly.

### Run the tests

```bash
pytest
```

## API reference

| Method | Path | Description | Success |
|---|---|---|---|
| `POST` | `/addresses` | Create an address | `201` |
| `GET` | `/addresses` | List addresses (`skip`, `limit`) | `200` |
| `GET` | `/addresses/{id}` | Retrieve one address | `200` |
| `PATCH` | `/addresses/{id}` | Update one or more fields | `200` |
| `DELETE` | `/addresses/{id}` | Delete an address | `204` |
| `GET` | `/addresses/nearby` | Addresses within a radius | `200` |

Errors: `404` for an unknown id, `422` for invalid input.

### Example: create an address

```bash
curl -X POST http://127.0.0.1:8000/addresses \
  -H "Content-Type: application/json" \
  -d '{"name":"Head Office","street":"1 Main Street","city":"Berlin","country":"Germany","latitude":52.52,"longitude":13.405}'
```

### Example: find addresses within 50 km

```bash
curl "http://127.0.0.1:8000/addresses/nearby?latitude=52.52&longitude=13.405&distance_km=50"
```

Each result contains the address fields plus `distance_km`, and results are ordered nearest first.

## Validation rules

- `latitude` must be between -90 and 90; `longitude` between -180 and 180.
- `name`, `street`, `city` and `country` are required, trimmed, and may not be blank.
- `state` and `postal_code` are optional.
- For `/addresses/nearby`, `distance_km` must be greater than 0 (up to half of Earth's circumference).

## Design decisions

- **Distance search.** Distances use the haversine great-circle formula (Earth radius 6371.0088 km). To avoid computing it for every row, a bounding box is applied first in SQL using the indexed latitude and longitude columns, and the exact distance is then checked on the remaining candidates. The box handles the antimeridian (±180° longitude) and the poles correctly.
- **Separation of concerns.** Business and persistence logic lives outside the route functions, which keeps endpoints thin and the logic testable.
- **Partial updates.** `PATCH` only changes fields the client actually sent, using Pydantic's `exclude_unset`.
- **Testing.** Tests override the database dependency with an in-memory SQLite database, so they never touch real data.

## Possible improvements

Database migrations (Alembic), authentication, duplicate-address detection, and a spatial index (e.g. SpatiaLite or PostGIS) if the dataset grows large.
